🧪 ThermoEqui-Agent RAG 核心架构

✅ 当前阶段：核心基础层（RAG Engine） · 状态：已完成并验证通过 · 最后更新：2026-07-28

1. 项目概述

本模块实现了 RAG（检索增强生成）系统的核心离线能力，包括文档加载、语义切分、向量化索引构建和混合检索。完全本地离线运行，不依赖任何外部大模型 API，使用开源的 Sentence-Transformer 模型将文本映射为语义向量。

核心特性

  • 多格式文档加载：支持 .md（Markdown）和 .yaml / .yml 配置文件。
  • 语义级别文本切分：基于句子向量相似度动态分割，避免机械截断句子。
  • 真实语义嵌入：集成 all-MiniLM-L6-v2 模型（384维），将文本转为稠密向量。
  • 本地向量存储：基于 NumPy 的 .npz 压缩格式持久化，零外部依赖。
  • 混合检索策略：结合向量语义相似度（70%）与关键词命中率（30%），提升召回精度。

2. 系统架构与数据流

模块依赖关系图

graph TD A[知识库文件
knowledge/*.md/yaml] --> B(loader.py
文档加载器) B --> C[Document 对象] C --> D(splitter.py
语义分割器) D --> E[Chunk 对象列表] E --> F(embedding.py
嵌入模型) F --> G[向量矩阵] E & G --> H(vector_store.py
向量存储) H --> I[vector_store.npz
磁盘文件] J[用户查询 Query] --> K(embedding.py) K --> J1[查询向量] I --> L(retriever.py
检索器) J1 --> L L --> M[Top-K 相关结果]

数据流详细说明

  1. 加载（Load）：KnowledgeLoader 遍历 knowledge/ 目录，根据文件后缀（.md / .yaml）调用对应解析器，生成 Document 对象（包含原始文本、来源路径、分类、元数据）。
  2. 切分（Split）：SemanticSplitter 将长文档切分为语义完整的 Chunk 块。
    • 先按句子分割。
    • 使用嵌入模型计算相邻句子的余弦相似度。
    • 当相似度低于阈值（默认 0.5）时，标记为话题转变边界并切分。
  3. 向量化（Embed）：SentenceTransformerEmbedding 将每个 Chunk 的文本内容批量转换为 384 维浮点数向量。
  4. 索引（Index）：VectorStore 将 Chunk 及其对应的向量、元数据（来源、分类、ID 等）在内存中关联，并整体打包保存为 .npz 文件。
  5. 检索（Retrieve）：查询时，将查询文本转为向量，与存储中的所有向量计算余弦相似度，按分数降序返回 Top-K 结果。支持关键词加权修正。

3. 核心模块详述

3.1 文档加载模块 (loader.py)

类/方法功能描述
Document数据类，标准化文档结构：content(内容), source(相对路径), category(父目录名), title(标题), metadata(额外元数据)。
MarkdownLoader解析 .md 文件，使用正则提取首个一级标题（# Title）作为文档标题。
YamlLoader解析 .yaml 文件，尝试读取 model_name 或 name 字段作为标题，若无则使用文件名。内容以 YAML 格式序列化存储。
KnowledgeLoader门面类。 load_all() 递归加载 KNOWLEDGE_ROOT 下所有受支持的文件。 load_category(category) 按子文件夹分类加载。

路径映射：

KNOWLEDGE_ROOT = Path(__file__).resolve().parents[1] / "knowledge"
# 假设项目结构：项目根目录/knowledge/工程案例/xxx.md

3.2 文本分割模块 (splitter.py)

类核心参数策略
MarkdownSplitterchunk_size=500
chunk_overlap=50		备用方案。按标题（#, ##, ###）切分为大段，再按字符数硬切分。
SemanticSplitter (当前默认)max_chunk_size=500
min_chunk_size=50
similarity_threshold=0.5		核心方案。基于句子向量相似度动态分割，保持语义完整性。当累积长度超过最大限制时强制分割。

语义分割算法伪代码：

1. 将文档分割为句子列表 S = [s1, s2, ..., sn]
2. 计算所有句子的向量 V = embed(S)
3. 计算相邻句子的余弦相似度 Sim[i] = cosine(V[i], V[i+1])
4. 遍历句子:
   - 若 Sim[i] < threshold 且 当前累积长度 > min_chunk_size => 切分
   - 若 当前累积长度 > max_chunk_size => 强制切分（兜底）
5. 合并过小的碎片块（< min_chunk_size 的合并到下一块）

3.3 嵌入模型模块 (embedding.py)

类说明
HashEmbedding降级方案。仅用于离线测试，基于 SHA256 哈希生成伪向量（不具备语义能力）。
SentenceTransformerEmbedding (当前默认)封装 HuggingFace 的 Sentence-Transformer。自动下载 all-MiniLM-L6-v2 模型（~90MB）。输出 384 维归一化向量。

初始化逻辑：

try:
    DEFAULT_EMBEDDER = SentenceTransformerEmbedding()
except ImportError:
    DEFAULT_EMBEDDER = HashEmbedding()  # 降级并警告

3.4 向量存储模块 (vector_store.py)

方法功能
add(chunks, embeddings)将块列表和向量列表配对存入内存 records。
search(query_embedding, top_k)暴力计算余弦相似度。阈值硬编码为 0.1，低于该值的向量结果将被过滤。
save(path)使用 np.savez 保存为 .npz 文件，包含 6 个数组（嵌入矩阵、文本内容、来源、分类、块 ID、总块数）。
load(path)从 .npz 重建 VectorStore 对象。

存储路径： 项目根目录/data/vector_store.npz

3.5 检索入口模块 (retriever.py)

方法说明
build_index()全量构建索引。清空现有向量库，重新加载所有文档 -> 分割 -> 嵌入 -> 保存。
retrieve(query, top_k)纯语义检索。将查询转为向量，搜索向量库返回 Top-K。
retrieve_with_keywords(query, top_k)混合检索（推荐）。先召回 2*top_k 个语义结果，再用关键词匹配分数加权重排。
from_loaded_store()类方法。直接加载磁盘上的 .npz 文件初始化检索器，跳过耗时重建，用于服务启动。

混合检索加权公式：

最终得分 = 语义相似度 * 0.7 + 关键词命中率 * 0.3

6. 当前限制与未来演进方向

6.1 已知限制

  • 向量检索复杂度 O(N)：当前使用暴力全量计算，在 向量块 < 10,000 时响应迅速，超过该数量级后性能将急剧下降。
  • 内存全量加载：启动时将整个 .npz 文件读入内存，占用随数据量线性增长。
  • 不支持增量更新：新增文档需调用 build_index() 全量重建。
  • 无元数据过滤：检索时无法限制特定分类（如只搜 fundamentals）。

6.2 下一步计划（服务/接口层 & 优化）

  • API 服务层：使用 FastAPI 封装 /retrieve 接口，支持前端/Agent 调用。
  • 向量引擎升级：替换 VectorStore 为 FAISS 或 ChromaDB，支持 HNSW 索引和增量更新。
  • 重排序（Reranker）：引入 Cross-Encoder 模型对初筛结果进行精排，提升精准度。
  • 配置外部化：将阈值、路径等硬编码参数迁移到 .env 或 config.yaml。
